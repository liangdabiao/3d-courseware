# 教学设计方法论（铜匠实验室课件的内容内核）

> 54 门课件的共同点不在 3D 技术，而在**内容结构**。本文档描述这套课件的教学设计法：
> 先想清楚「主线问题」，拆成因果链，再把每一环做成一个「动手-观察-结论」的步骤。

## 0. 一门课的诞生流程（设计顺序）

1. **定位**：从课标+教材（人教版 2019）选一个点，确定类型：`原理与现象`（39 门）/
   `工业流程`（9 门）/ `原理与实验`（5 门）。写 `locate`（教材章节）与 `ref`（课标条目，如 A2.1、B2.4）。
2. **主线问题**：一个学生真正关心的、可感知的问题，全课只回答它。
   - 好例子：「一块银白色的小金属，为什么必须泡在煤油里，着火时连水都不能浇？」（钠）
   - 好例子：「怎样把空气里的氮又快、又多、又省地变成氨？」（合成氨）
   - 好例子：「长江镇江段的岸线为什么持续向北推移？」（河流地貌——用真实地名锚定）
   - 写法：具体可感（银白色小金属）+ 悬念冲突（连水都不能浇）+ 可回答（整课步骤就是答案）。
3. **知识链（chain）**：把答案拆成 4–6 环因果链，每环 `{k: 短语, t: 一句话}`，环间用箭头 `seps`
   （普通 `→`、双向 `↔`、协同 `＋`）。这条链常驻顶栏，是全课的「地图」。
   - 钠：最外层1个电子 → 见氧就变 → 见水更凶 → 所以不能用水 → 只能用干砂
   - 合成氨：平衡 → 速率 → 限制 → 折中 → 循环
4. **步骤规划**：7–9 步（全库 6–9 步，众数 9）。第 1 步「认识实验台/沙盘」（orbit 熟悉场景），
   中间每步对应知识链一环，最后一步固定是**考核**（tag 带「考核·当XX」）。
5. **每步教学化**：按 §2 的字段规范写内容。核心纪律：**每一步都有动手、有可量化观察、
   有教材原话结论、有考点、有易错点防护。**
6. **世界观设计**：3D 站位/布景承载这些步骤（见 architecture.md §world）。

## 1. 课程内容对象 C 的顶层结构

```js
C = {
  meta:  { slug, subject:"高中化学", type:"原理与现象", locate:"人教版必修…", title, cover },
  top:   { title, total },          // total: 全课总式/总括一句话，常驻顶栏课名旁
  mainline: { q, chain:[{k,t}…], seps:["→"…] },
  ui:    { crumb, subAll, panel:{sub}, quiz:{allRight, retry} },
  layers: { 名称: 一句话说明 },      // 每个图层/微观视角的教学含义
  units: [ {no:"①", name, short, brief, color:1..5} … ],   // 站位（一般 ≤5 个，识别色 1–5）
  panel: { … },                     // 中控台全部文案（读数标签、滑杆刻度、开关文案、风险依据…）
  steps: [ … ],                     // 6–9 步，见 §2
  toast: { … },                     // 操作反馈语（每个开关/事件的 on/off 都有具体句子）
  quiz:  { list:[{tag, unit, q, opts[4], ans, why} …] },    // 检测：每站位至少 1 题 + 综合 1 题
  foot:  { note, keys:[["Esc","回到控制台"]…], goal },       // goal: 本课目标一句话
  accident: { check, trip, unit, countdown, estop },        // 可选：事故模拟（工业/危险实验）
  section: { head, note, subs, canvasHead, canvasStages, canvasNote, canvasSum },  // 可选：讲义图
}
```

写作纪律（从 54 门课提炼）：

- **所有数字必须与 model 的计算一致**。expect 里写「60 s → 6.1 mmol、光泽 30.1 %」，
  就要真的由仿真模型算出来；面板读数注释（cal）写「教材 p.36」「标准状况」注明依据。
- **教材原话入课**：concl 引用教材表述并标注页码（p.34/p.35），ref 写课标编号（A2.1）。
- **文案是第二老师**：toast 不写「操作成功」，写「已泡在煤油里——煤油把空气挡住了」；
  quiz.retry 不写「答错了」，写「建议回看主线：先看…再看…最后看…」。

## 2. 步骤（step）字段规范 —— 每一步的完整教研结构

```js
{
  no: "①", tag: "认识实验台",       // tag ≤ 6 字，步骤条上显示
  q: "一块银白色的小金属，为什么…？", // 本步驱动问题（17px 加粗，是本步的标题）
  unit: 0,                          // 聚焦站位（-1=全场景；运镜+名牌+面包屑都跟它走）
  layers: ["look"],                 // 本步显示哪些图层（"all"=全部；与 world.LAYERS 对应）
  hi: "t",                          // 本步要动的中控台控件 key → 控件高亮「本步」
  act: { kind, text, … },           // 动手任务（见 §3）；text 是给学生的操作指令
  expect: { text, …numbers },       // 预期观察：含具体数字的现象描述（学生对照自查）
  concl: "…（教材原话）（p.XX）",    // 结论：完成操作后展示
  ref: "A2.4、B2.5、标准值表 2–4",   // 课标/教材出处
  points: [ …, "去掉这一步：学生会…" ],  // 讲解要点；最后一条固定写「去掉这一步」的后果（易错点防护）
  exam: "高频：…；常考：…",          // 考试怎么考（whybox 展示）
  eq: "4Na + O₂ = 2Na₂O",           // 本步的式子（若有）→ 显示在公式横幅 #eqb
  eqCal: "常温 · 敞口放置 · 新切开的切面",  // 式子的条件标注
  tags: ["0 → 8.7 mmol", "光泽 100%→0.2%"],   // 关键数字标签（横幅下方胶囊）
  start: { t: 0, oil: false },      // 进入本步时中控台状态（缺省沿用上一步；startMode:"keep"）
  cam: { box:{min:[x,y,z],max:[x,y,z]}, pitch:20 },  // 本步运镜目标框（世界坐标，米）
  chain: 1,                         // 本步点亮知识链第几环（"all"=全部）
  // 记录型步额外：act.kind="record" + CONSOLE.record 配置（见 architecture.md）
  // subSeq: {keys:[…], every}     副读数轮流点亮（讲解节奏）
  // prep: (ctx, want)=>void       进步前准备钩子
}
```

**expect 的写法**（最重要）：不是「钠会变暗」，而是
「敞口放置：0 s 银白色（0.0 mmol，光泽 100%）→ 10 s 已变暗（1.6 mmol，81.9%）→
60 s 整块变暗（6.1 mmol，30.1%）→ 300 s（8.7 mmol，0.2%）；煤油瓶里那块钠一直是银白色的」。
—— 时间线 + 数字 + 对照物。学生拿着这个清单看场景，能自己判断「我看到了吗」。

**points 的写法**：前几条是正面讲解（「变暗不是脏了，是表面生成了一薄层 Na₂O」），
最后一条固定是「去掉这一步：…」——写出若跳过此步学生会形成的迷思概念
（「学生以为钠本来就是灰的，不知道银白色才是它本来的样子」）。这是整套课件的灵魂设计：
**每一步都在防御一个具体的、可预见的学生错误**。

**act 的设计原则**：第一步永远是 orbit（先自由视角认场景）；每步的动手动作必须
能触发一个可观察的变化（动一个控件 → 场景+读数一起变）；考核步 kind="hold"。

## 3. 动手任务（act）类型

| kind | 语义 | 额外字段 |
|---|---|---|
| `orbit` | 拖动视角环绕认场景 | — |
| `slider` | 把某滑杆拖到阈值 | `key, op:">="/"<=", to, demo` |
| `toggle` | 拨动某开关到目标态 | `key, want:true/false` |
| `watch` | 观察一段动画播放完 | `secs` |
| `custom` | 复合操作（多控件组合、扫零点等） | `ok:(ctx)=>bool, demo:async(ctx)=>{…}, secs` |
| `record` | 记录数据行（n 组） | `n, states/demo`（配 CONSOLE.record 表） |
| `hold` | 考核保持：条件成立保持 X s | 需配 CONSOLE.exam |

每个 act 都要配 **demo**（自动演示脚本）：点击可自动完成操作，方便老师演示和学生卡关时自救。

## 4. 检测（quiz）设计

- 题量 5–8 题；每站位至少 1 题（tag 带站号）+ 1 综合题；答对每题 +5 分（记入 HUD 得分）。
- 选项 = 3 个**典型迷思概念** + 1 个正确项。干扰项要写成像样的答案（电解水/分解氨/降温）。
- `why` 逐项点破：不只解释正确项，要点破错误项为什么错（「催化剂不移动平衡」「平衡常数只随温度变」）。
- 答错显示 `unitGo` 跳转链接：「去 ② 净化 步」一键回到对应站位重看。
- 全对/需复习的反馈语写在 `ui.quiz.allRight/retry`，retry 给出回看路径（先看…再看…最后看…）。

## 5. 考核（最后一步）设计

- tag 命名「考核 · 当XX」（当实验员/当班长/当滴定员）——角色扮演式考核。
- 考核步：`act.kind:"hold"` + `CONSOLE.exam` 配置：
  - `ok(S,R)` 达标判定（复合条件）；`hold:15` 保持 15 秒；`score:15` 通过加分。
  - `events:[{at:6, set:{way:2}, toast}]` —— **考核中途出变故**（6 秒时有人把砂土换成水…），
    学生必须响应回来。这是「理解了」和「背下来了」的分水岭。
  - `solve` 参考解状态；`goal:{title, tip, short}` 目标条文案（short 是紧凑档简写）。
- 工业课考核通常叠加**事故系统**：`accident.trip`（超温/超压阈值）→ 倒计时（「3 秒内不降温将破裂」）
  → 若不处理：全屏红闪 → 事故复盘（因果链 + 预防清单 + 教训）→ 抢修 → 重开。
  `estop` 紧急停车把状态钳回安全值。

## 6. 主线与导航体验

- 顶栏常驻：主线问题（「主线」徽标 + 问题）+ 知识链胶囊（当前步点亮对应环，进行中的环渐变描边）。
- 步骤条可点击任意跳转；底栏 上一步/「3 / 9」/下一步，快捷键（N 名牌、Q 检测、F 全屏、Esc 回控制台）。
- 每步切换：运镜到 `cam.box`（平滑插值）+ 应用 `start` 状态 + 切 `layers` + 高亮 `hi` 控件 +
  名牌/面包屑更新。学生永远知道「我在哪、我要干什么、我该怎么判断做对了」。

## 7. 中控台文案（C.panel）写作规范

- 主读数 label 是教学语言：「已转移电子 n(e⁻)」，不写「n_e」。
- 每个读数都有 `cal` 依据注释：「每个钠原子失去 1 个电子 · 课件设定 · 教材 p.34」——
  读数的来历要可追溯（教材/标准状况/课件设定 三类，课件设定要明说）。
- 滑杆要有刻度语义（ticks + fmt），档位滑杆用枚举名（「① 观察站」「② 氧气站」…）。
- 开关的 on/off 文案不对称：on:「已泡在煤油里」，off:「已取出放在玻璃片上」——描述**状态**而非动作。
- 风险条（若有）：`cal` 写清公式含义（「钠块越大、灭火方式越错，风险越高」）+ warn 阈值。

## 8. 质量红线（写完自查）

1. 每一步都有：驱动问题 q、动手 act、量化 expect、教材依据 concl+ref、考点 exam、易错点防护 points。
2. 所有 expect 数字与 model 输出一致（亲自跑一遍核对）。
3. quiz 干扰项是迷思概念而非凑数选项；why 点破每个错误项。
4. 考核有中途变故（events）或有事故（accident），不是静态答题。
5. 主线问题在最后一步被显式回答（考核 goal 就是主线问题的行动化）。
6. 全中文、教材同步（人教版 2019 章节定位）、无跨教材超纲表述。
